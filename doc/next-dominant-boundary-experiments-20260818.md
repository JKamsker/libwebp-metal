## Selection and deferrals

Two diagnostic experiments are selected. They answer the semantic-boundary
questions needed before an expensive GPU implementation. They do not claim a
speedup and they cannot promote production code directly.

1. `predictor_boundary` splits selector/search, final residual application,
   and nested predictor-map encoding. The candidate is the broader future
   selector+apply boundary. A residual-only candidate is explicitly excluded.
   If map encoding is material, the present CPU bit-writer dependency makes a
   resident map path non-credible and the implementation is deferred.
2. `backref_exact` splits standard exact LZ77 selection, RLE, box search, cache
   search/rewrite, trace-back, cost evaluation, and inclusive total. The only
   candidate is future exact-candidate evaluation with CPU serial choice and
   cache semantics retained.

Rejected now:

- another standalone predictor-residual Metal dispatch, because the completed
  experiment is negative and does not cover selector or map encoding;
- multiplying any new stage share or future ratio by the historical hash or
  end-to-end ratio;
- threshold/content tuning from this one generator per category;
- a GPU bit-writer, GPU linked-list `VP8LBackwardRefs`, or descriptor ABI
  extension before the diagnostic holdout criteria establish a boundary.

Deferred rather than selected:

- a fused/resident predictor implementation; its exact boundary depends on the
  new selector/apply/map split;
- a Metal backward-reference selector; variable-length serial decisions,
  progress/cancellation, cache mutation, and transactional linked blocks make
  it premature until exact candidate evaluation is shown dominant;
- natural-image or cross-device claims. Publication corpus v1 is controlled
  synthetic evidence, and this cycle remains one physical Metal device.

## Isolation and behavior

| Experiment | New build flag | New private macro | New exact runtime flag |
|---|---|---|---|
| predictor boundary | `WEBP_BUILD_PREDICTOR_BOUNDARY_EXPERIMENT` | `WEBP_USE_PREDICTOR_BOUNDARY_EXPERIMENT` | `WEBP_PREDICTOR_BOUNDARY_EXPERIMENT=1` |
| backref exact | `WEBP_BUILD_BACKREF_EXACT_EXPERIMENT` | `WEBP_USE_BACKREF_EXACT_EXPERIMENT` | `WEBP_BACKREF_EXACT_EXPERIMENT=1` |

Both default off and are independent of item 1--5 and each other. Default
CMake and `makefile.unix` builds omit `boundary_experiment_enc.c`, its symbols,
its environment reads, and the corresponding `cwebp` repetition option.
Autotools has no option for these experiments and therefore also omits them.
Each timed entry point requires its exact runtime flag and
`WEBP_BENCHMARK_SESSION=exclusive`; absent, non-exclusive, or invalid states
refuse before corpus generation, build, or timing.

Record and matched control variants use the same binary and runtime opt-in.
Control retains only session/total recording and omits substage clocks. Record
adds the non-overlapping substage probes. Recorder open/write failure and the
dedicated failure-injection path abandon evidence output without changing the
encoder result. Correctness tests require record, control, repeated record, and
injected-failure bitstreams to be identical.

## Frozen protocol

The machine-readable authority is
`scripts/next_boundary_experiments_v1.json`. It fixes hypotheses, mechanisms,
inputs and hashes, tune/holdout roles, methods 4 and 6, cold/warm lifecycle,
pair order, run counts, schemas, metrics, uncertainty, p95 rules, acceptance
and rejection, resource ceilings, duration estimates, and evidence paths.
`scripts/run_next_boundary_experiments.py` accepts only an experiment id and a
new output directory; no parameter, criterion, corpus, order, or run-count
override exists.

Cold is one measured encode in a fresh process. Each cold cell has seven
alternating record/control process pairs. Warm is one process with one
discarded warmup followed by five measured encodes; each warm cell has three
alternating process pairs. Warm observations within a process are correlated,
so inferential resampling is over process-pair medians, not individual warm
encodes. Tune and holdout, method, lifecycle, content, and experiment are never
pooled. A fixed bootstrap seed is used only to describe uncertainty; it does
not change a decision threshold.

Predictor uses `photo-medium` for tune and `photo-large` for holdout. Backref
uses `texture-medium` for tune and `texture-large` for holdout. All nine
publication cases at both methods are correctness/determinism/fallback guards.
There is one hypothesis and one fixed boundary per experiment, so no best-of
candidate or threshold search is allowed. Both methods and both cold/warm
holdout cells must pass every criterion.

Raw encoder records use `libwebp-predictor-boundary-v1` or
`libwebp-backref-exact-v1`. Command records use
`libwebp-boundary-command-v1`; correctness uses
`libwebp-boundary-correctness-v1`. Raw records preserve nanoseconds and call
counts. Evaluation must report paired medians, MAD, fixed-seed bootstrap
intervals over process-pair medians, nearest-rank p95, every required stratum,
and any failed/missing record. P95 or median recorder/control overhead above
the frozen limits rejects the measurement as distorted.

The operator enforces one non-blocking host lease at
`/tmp/libwebp-metal-next-boundary.lock`, one process at a time, command and
total duration ceilings, artifact size, clean worktree, exact expected commit,
and corpus hashes. The manifest fixes an 8 GiB free-memory prerequisite, 6 GiB
observed-RSS ceiling, 2 GiB artifact ceiling, 240-second command ceiling, and
60-minute per-experiment ceiling. A failed prerequisite stops the experiment;
the executor must not improvise. Once the lease has been acquired, any failure
also emits `failure.json`, a failed operator report, resource notes confirming
lease release, and hashes for all evidence preserved up to that point.

After the coordinator supplies the immutable designer commit as `<commit>`,
the only timed commands are, strictly one after the other:

```sh
WEBP_EXPECTED_DESIGNER_COMMIT=<commit> \
WEBP_BENCHMARK_SESSION=exclusive \
WEBP_PREDICTOR_BOUNDARY_EXPERIMENT=1 \
python3 scripts/run_next_boundary_experiments.py run \
  predictor_boundary /absolute/new/evidence/predictor-boundary

WEBP_EXPECTED_DESIGNER_COMMIT=<commit> \
WEBP_BENCHMARK_SESSION=exclusive \
WEBP_BACKREF_EXACT_EXPERIMENT=1 \
python3 scripts/run_next_boundary_experiments.py run \
  backref_exact /absolute/new/evidence/backref-exact
```

The second command must not begin until the first has completed and released
the host lease. No CUDA build, source, command, or interpretation is part of
this protocol.

## Untimed designer validation

The designer may run only:

```sh
python3 scripts/run_next_boundary_experiments.py validate
python3 scripts/test_experiment_guards.py
python3 scripts/test_next_boundary_experiments.py
```

The last command builds and runs correctness workloads but performs no
performance comparison, aggregation, or acceptance decision. The `validate`
command refuses an exclusive benchmark session so it cannot accidentally
enter the timed phase.
