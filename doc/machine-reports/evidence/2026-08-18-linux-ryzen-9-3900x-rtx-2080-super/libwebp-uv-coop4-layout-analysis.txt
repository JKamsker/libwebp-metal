Candidate shared-layout analysis
================================

kCudaYuvSizeEnc = 32 * 16 = 512 bytes
kCudaPredSizeEnc = (32 + 16 + 8) * 32 = 1792 bytes

Three YUV buffers:                 1536 bytes
Two prediction buffers:           3584 bytes (running offset 5120)
y_left + uv_left + y_top + uv_top:   78 bytes (running offset 5198)
padding before pred_dc:               2 bytes (running offset 5200)
pred_dc:                             12 bytes (running offset 5212)
i4_boundary:                         37 bytes (running offset 5249)
padding for int16_t i16_tmp:          1 byte  (field offset 5250)

5250 modulo alignof(int) is 2. Reinterpreting `i16_tmp` as `int*` therefore
created misaligned 32-bit shared accesses. The candidate kernel failed and
the encoder's transactional CPU fallback preserved exact output.

The candidate was corrected by adding `alignas(4)` to `i16_tmp`. That version
executed successfully and was profiled and validated as the same sole
candidate. It reduced UV numerical block-cycle share from 5.1% to 3.4%, but
end-to-end paired medians regressed in both formats.
